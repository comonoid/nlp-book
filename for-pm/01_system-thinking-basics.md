# Что такое системное мышление

<small>← [Введение для PM](00_pm-intro.md) · [Далее: Обзор инструментов →](02_tools-overview.md)</small>

🟢 Базовый · ⏱ 3 мин

*Линейное мышление ищет виноватого. Системное — ищет паттерн, который порождает проблему снова и снова.*

<details>
<summary><b>Кратко</b></summary>

- Системное мышление — способность видеть целое, связи и петли обратной связи
- 5 ключевых принципов: целостность, взаимосвязи, обратная связь, множественность описаний, эмерджентность
- Отличие от линейного: циклы вместо цепочек, паттерны вместо виноватых

</details>

---

Системное мышление — способность видеть **целое**, а не только части. Видеть **связи** между элементами, а не только сами элементы. Понимать, что изменение в одном месте влияет на другие.

## Ключевые принципы

| Принцип | Что означает | Пример для PM'а |
|---------|--------------|-----------------|
| **Целостность** | Система ≠ сумма частей | Проект — не набор задач в Jira, а живой организм с отношениями, рисками, культурой |
| **Взаимосвязи** | Элементы влияют друг на друга | Задержка в одном модуле тормозит интеграцию, интеграция тормозит тестирование |
| **Обратная связь** | Петли усиления и балансировки | Маленький успех → рост доверия → больше автономии → больший успех. Или наоборот. |
| **Множественность описаний** | Разные люди видят разное | Один проект — три картины: для бизнеса, для разработки, для пользователей |
| **Эмерджентность** | Новые свойства на уровне системы | «Работающий продукт» возникает из взаимодействия, а не из суммы фич |

## Отличие от линейного мышления

| Линейное мышление | Системное мышление |
|-------------------|-------------------|
| Причина → Следствие | Циклы обратной связи |
| Найти виноватого | Найти паттерн |
| Исправить симптом | Изменить структуру |
| «Кто это сделал?» | «Что в системе это порождает?» |
| Один правильный ответ | Множество точек зрения |
